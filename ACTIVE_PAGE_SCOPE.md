# Active Business Page Scope

Audit date: 2026-07-31

This report corrects the earlier endpoint-count interpretation. A PHP file is not automatically a screen. The classification starts with visible, non-commented legacy navigation, then uses legacy permission data, form/redirect dependencies, visible page structure, and the modules already represented in NewProject. No functional code was changed.

## 1. Corrected Counts

### Endpoint classification

The 1,865 first-party records in `LEGACY_INVENTORY.tsv` were assigned once to a primary static category. The categories describe physical PHP entries; the main-page count is then consolidated by business concept.

| Classification | PHP entries | Counting rule |
|---|---:|---|
| Active user-facing menu entry variants | 170 | Direct menu evidence, including root/branch/admin copies |
| Child/detail pages | 149 | Detail, timeline, receipt, view, or subordinate form attached to a parent |
| Form/action handlers | 65 | Result, submit, update, upload, delete, confirmation handlers |
| AJAX endpoints | 139 | Graph/select/input/data/JSON helper responses |
| Print/PDF/export endpoints | 289 | Dedicated PDF, TCPDF, print, XLS/XLSX, or export output |
| Public token/reply endpoints | 27 | Public check/reply/token/callback flows |
| Shared includes/helpers | 88 | Headers, footers, sessions, classes, configuration and shared utilities |
| Duplicate or alternate versions | 156 | `Bk`, numbered, backup, or alternate-rendering candidates |
| Legacy unused/dead candidates | 10 | Test, empty, setup, and diagnostic files with no active-menu evidence |
| Unknown pending production evidence | 772 | Cannot be safely assigned active/dead/duplicate from source alone |
| **Total** | **1,865** | Mutually exclusive static working classification |

The 170 menu-linked physical variants resolve to **121 unique literal PHP targets**. After attaching known child pages (`*_complete_documents`, evaluation view, transferal home), merging the evidenced `info.php/info1.php` alternate, and treating logout as an action, the corrected result is **115 active main user-facing business/profile/administration pages** across the entire legacy system.

This does **not** mean 115 pages belong to the current delivery. Seventy-five are active legacy pages in legal, clinical operations, finance, reports, messaging, or reference administration that are not represented in NewProject and therefore need explicit client inclusion. The database dump provides only 10 general `page` rows and 12 rows in the separate `permissions` table; current production permission/menu data remains necessary to settle the 772 unknown entries.

### Evidence hierarchy

1. Non-commented employee, branch, and admin menu links.
2. Current `page` and `permissions` rows in the supplied legacy dump.
3. Page-visible forms and titles plus redirects/links from an active parent.
4. Branch/company/user-level conditions in the corresponding shell/page.
5. Presence of an equivalent NewProject module and route.
6. Filename inference only as a final classifier; it is not proof of obsolescence.
